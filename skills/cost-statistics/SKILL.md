# 成本统计报告

输入各对象已有的过程指标统计Excel，交付成本统计报告.docx。默认封面一页、正文一至两页；以汇总表和两张横向条形图为主，配两至三段基于数值关系的分析。统计值由脚本复算，报告文字由执行Agent结合实际汇总撰写。

## 输入和运行

用户提供目录时发现其中各对象的 `_过程指标统计.xlsx`，跳过 `~$` 临时文件。也可明确指定多个文件。按对象名称识别，不固定对象数量、题目数、数据集数量和执行次数。同对象存在多个批次时根据用户范围选择，不将不同批次直接叠加。未给结果目录时在当前任务目录创建 `成本统计报告/时间戳`。范围已明确时直接执行，不重复追问现有信息。

先读 [统计规则](references/statistics.md)，再运行：

```powershell
python <skill目录>/scripts/aggregate.py --input-dir "<Excel所在目录>" --output "<工作目录>/汇总数据.json"
```

显式指定对象或文件：

```powershell
python <skill目录>/scripts/aggregate.py --input "MobileWork=<Excel路径>" --input "WorkBuddy=<Excel路径>" --output "<工作目录>/汇总数据.json"
```

仅使用任务均值表和逐次记录表，不重跑测试，不回查端侧日志，不改写源Excel。聚合脚本只需Python标准库；Word生成依赖本技能的requirements.txt。优先使用宿主依赖运行时，缺少库时在任务环境安装。字体缺失可用report.py的 --font 指向本机中文字体。

## 分析和报告

阅读汇总JSON中的共同题目、均值、有效题数、逐次样本数及数值派生关系。覆盖不一致时用共同题目比较；具体排除项及证据保留在本地汇总JSON。只有真实缺失或口径冲突影响理解时才简短说明，不添加例行声明。

按 [报告规范](references/report.md) 写分析JSON，格式为 `[{"heading":"标题","text":"正文"}]`，两至三段为宜。分析解释有依据的联系，例如调用次数与单次输入规模、较长运行对均值的影响、工具调用量与错误占比；不逐项复述表格。MobileWork参与时适度多分析其实际表现，兼顾其他对象，不声明主次，不预设优势。不得沿用旧报告的具体结论、数字或任务名称。

```powershell
python <skill目录>/scripts/report.py "<工作目录>/汇总数据.json" --analysis "<工作目录>/分析.json" --output "<结果目录>/成本统计报告.docx"
```

不带 --analysis 可生成当前数据的初稿观察，执行Agent仍需检查准确性、分析价值和篇幅。报告不写样本规模警告、通用防御性表述、数据来源章节，也不写后续合并报告或制作Skill的计划。样本规模作为真实封面信息动态填写，不固化测试批次说明。

## 版式和交付

风格见 [版式规范](references/layout.md)，可查看打包的 [风格参考报告](references/style-reference.pdf)，只参考视觉样式。封面标题为成本统计报告，副标题为执行过程消耗对比。主表仅保留规范中的十项指标，均值名称明确标注平均；P50、P95注明分位数口径。正文不放逐题明细表。两图分别呈现平均总Token和平均端到端耗时，各对象保持相同配色。

生成后渲染并逐页检查。可用宿主文档工具；本技能提供预览助手：

```powershell
python <skill目录>/scripts/render_preview.py "<结果目录>/成本统计报告.docx" --output "<工作目录>/预览"
```

Windows使用后台WPS或Word导出，其他环境可指定 --soffice；PDF转图需要pdftoppm，可用 --pdftoppm 指定。检查正文不超过两页、表格可编辑且不越界、图中文字清楚、对象配色一致、数值及百分比正确。超页优先精简分析或调整图表布局，不删除对象或缩小到难以阅读的字号。

最终只交付Word报告，汇总JSON、分析JSON和预览留作本地核查。确认文件保存、渲染和检查完成后再宣称交付完成。
